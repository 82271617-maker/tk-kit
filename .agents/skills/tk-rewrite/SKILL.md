# 文案三步（外语 → 中文 → 中文调整稿）

一句话：**机器做执行，人做判断；做到 03 就停。**

## 输入

- 素材：`02-去水印/<id>-clean.mp4`（没有就用 `01-素材/<id>.mp4`）
- 输出目录：`03-文案/<id>/`
- 语种：用 `--lang` 指定（en / ja / ko / zh），不知道先试 auto

## 三步

```bash
KIT="${KIT:-$HOME/tk-kit/kit}"; ROOT="$HOME/Desktop/TK素材"
D="$ROOT/<年-月>/<年-月-日>/<编号>-<id>/03-文案"

# ① 转写（脚本，不许自己听写）
HF_HOME=$PWD/.cache/hf $KIT/.venv-asr/bin/python $KIT/transcribe.py \
  "$ROOT/.../<id>/02-去水印/<id>-clean.mp4" --lang en --out "$D"
# 产出 01-英文稿.txt + 01-英文稿.srt
```

② 初翻（英文 → 中文）写 `02-中文稿.txt`：

1. 按中文习惯表达，不生硬直译，不改变叙事顺序
2. **语句之间不加任何标点**
3. **一句一行，行数与 01 完全一致**（不合并、不拆分）
4. 血腥暴力词改中性说法
5. 自检：行数相等？有没有混入标点？

②.5 评论取料（改写之前必做，不许跳过）

先读 `03-文案/<id>/00-评论.md`（tk-select 阶段 3b 已生成）。没有就现场抓：

```bash
KIT="${KIT:-$HOME/tk-kit/kit}"
.venv/bin/python "$KIT/comments.py" <视频链接> --pages 4 --top 20 --dump-md "$D/00-评论.md"
```

从里面取三样，写进 `03-说明.txt`：

1. **观众最强 2–3 句原话**（带赞数）
2. **观众在为什么激动**（愤怒/感动/质疑/追责，一句话）
3. **争议点**（如果 40% 以上在吵「真假/摆拍」，那本身就是钩子）

**规则：改写的钩子必须能在评论里找到原型。** 评论说「她只顾打电话」但原片是包掉地上——
以原片为准，不照抄评论；评论的用处是**告诉我们开头该抓哪根神经**，不是编情节。

③ 改写（中文 → 调整稿）写 `03-调整稿.txt`：

1. 改成「准备翻日语」的口播中文：短句、直给
2. 不用成语、歇后语、网络梗
3. 不加标点，一句一行，**行数与 02 一致**
4. **总字数比 02 少 30% 以上**
5. 开头三句必须是钩子：冲突 / 反常识 / 悬念——**而且这个钩子要来自 ②.5 的评论取料**：
   观众最激动的那一点，必须出现在前三句里（「观众感兴趣的前置」）
6. 允许倒叙：先给结果再回去讲原因（画面需配合重排）

## 发布文案（标题 / 正文 / 标签）

在三步之外，额外产出一份 `发布文案.txt`（跟 03 放同一个目录），**给发布用，不参与配音**：

```
第 1 行 = 标题（一句话）
第 2 行 = 正文（一句话，短）
第 3 行 = 标签
```

规则：

1. **标题一句话**：钩子优先（冲突/反常识/悬念），不写问句堆叠，不超过 40 个日文字符
2. **正文一句话**：补信息或抛问题，不超过 60 个日文字符，不重复标题
3. **标签 ≤ 5 个**，其中 **`#速報` 和 `#news` 必须有**，剩下 3 个按题材选（`#海外ニュース` `#感動` `#涙` 这类）
4. 语言跟成片一致（日语片写日语），专有名词保留原文
5. 不堆 emoji，不写「必ず見て」这类诱骗词

样例：

```
電車のドアが閉まった瞬間、ホームに残されたのは赤ちゃんだけだった
車内に取り残された母親は窓を叩き、通りかかった男が代わりに赤ちゃんを守っていた。
#速報 #news #海外ニュース #感動 #涙
```

## ④ 人审门禁（硬卡点，必须弹窗 + 等人回话）

写完 `03-调整稿.txt` 后，**立刻停下**，做三件事：

```bash
open "<03-文案/<id>>"                    # 打开目录
open "<03-文案/<id>>/03-调整稿.txt"       # 打开调整稿
open "<03-文案/<id>>/03-说明.txt"         # 打开钩子与疑点
```

然后**弹三选一**（用 ask_user_question，不要只发一句话）：

| 选项 | 文案 | 选完做什么 |
| --- | --- | --- |
| ① | 审核通过（内容没问题，往下翻日文） | 立刻生成 `04-已审核.txt`，进 ⑤ |
| ② | 我提意见，你来改（告诉我改哪句） | 等用户输入意见 → 改 03 → **重新弹这三个选项**，不自动往下 |
| ③ | 我自己改文件（已打开，改完回来说一声） | 什么都不做，等用户回话；他回来后再弹一次三选一 |

配套准备一个粘贴区：`03-文案/<id>/03-修改意见.txt`（预置三行提示），
用户想一次说多条意见时，让他们写在里面，你读这个文件即可，不用在对话里长段输入。

**在选①或用户明确说「审核通过」之前，什么都不许往下做**——不写日文稿、不配音、不改 05。

### 收到「审核通过」之后

才允许生成 `04-已审核.txt`：

```
= 03-调整稿.txt 全文 + 首行记录：
# 已人工审核 · <姓名> · <YYYY-MM-DD HH:MM> · 原话：<用户这句>
```

这一步是**把人工放行留痕**，不是绕过人审：
- 没有用户明确说「审核通过」→ 生成 04 就是违规
- 04 的第一行必须写着谁、什么时候、原话是什么

### 之后

`05-日文稿.txt` 只从 `04-已审核.txt` 翻译，不从 03 翻。

## ⑤ 日文稿（照这段提示词执行，一字不改）

```
请将以下中文文案逐句翻译为日语。

翻译风格应符合 TikTok 讲述类视频的配音习惯，使用自然、口语化、情绪真实的日语表达。
每句中文对应一句日语，便于中日双语字幕对照。
语言需具备节奏感、情绪张力和画面感，适合做旁白或字幕使用。
请避免使用生硬、书面语或不自然的表达，不能像论文翻译，要像一个人坐在镜头前，自然地娓娓道来。
不要增删内容，严格保持原文节奏和句式结构，一句不落。
翻译时应使用符合日本观众文化与语言习惯的说法，避免出现中式日语或不符合日本人习惯的说法。

【范例参考】
中文：我明明是个连蚊子都不敢拍死的废柴屌丝
日文：オレは蚊一匹も殺せない、ただのヘタレだ。
中文：看到地上的尸体我差点被吓尿
日文：床に転がる死体を見て、マジでちびりそうだった。

去掉中文 去掉标点符号 不要做其他改动 按顺序把日语排列下来
检查并修正错别字、人称，其他不做任何改变。
```

硬要求：

- **行数必须等于 04 的行数**（一句一行，不能合并/拆分）
- **日语行内不加任何标点**（不用 。、！？，用空格断句）
- 只输出日语，不附中文对照
- 人名/地名/数字保留原文，拿不准的写进 `05-说明.txt` 交给人工核

## 门禁（只认文件名）

- 有 `03`、没有 `04` → 停在④，等「审核通过」
- **AI 不许自己判断「审过了」**，也不许把自己的检查当成审核
- 有 `05-日文稿.txt` 但没有 `04-已审核.txt` → 判不合格（说明跳了人审）

## 校验（跑完必须过）

```bash
KIT="${KIT:-$HOME/tk-kit/kit}"
.venv/bin/python "$KIT/rewrite_check.py" "$D"
```

检查四项：行数 01=02=03、02/03 无标点、缩减 ≥30%、空行。

## 五步全貌

```
① 转写（脚本）→ 01-英文稿
②.5 评论取料 → 00-评论.md
② 初翻 → 02-中文稿
③ 改写 → 03-调整稿 + 03-说明
④ 人审（弹窗 + 等回话）→ 04-已审核
⑤ 日文稿 → 05-日文稿
```

## 产出

```
03-文案/<id>/
├── 01-英文稿.txt / .srt
├── 02-中文稿.txt
├── 03-调整稿.txt
├── 03-说明.txt      钩子 + 评论依据 + 疑点
├── 04-已审核.txt    人审留痕（没有它不许进 ⑤）
├── 05-日文稿.txt    从 04 翻译
└── index.json       {"01":…,"02":…,"03":…,"guard":"03"}
```

`03-说明.txt` 必须写：**钩子三句** + **评论依据**（哪句原话、多少赞、决定了哪个钩子）
+ **疑点**（原片没给的数字、性别、地名），并标明哪些是画面推断、哪些是评论误读不能采信。

## 边界

- 不编情节：原片没说的不补
- 不顺着评论区写（评论是「观众以为」，不是事实）
- 不做日语（那是 `tk-dub` 上游之前的独立一步）
