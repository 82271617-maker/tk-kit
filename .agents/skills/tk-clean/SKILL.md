# TK 素材准备：下载 + 去水印

一条命令把链接变成本地可剪素材；去水印**只遮文字所在的像素行**，不整块糊掉画面。

## 关键认知（先看这个，能省一半返工）

TikTok 的**平台水印在下载时就没了**（yt-dlp 拿的是源文件）。需要处理的其实是**原片自己烧录在画面上的文字**：

| 类型 | 长什么样 | 处理 |
| --- | --- | --- |
| 模板新闻片 | 顶部 `BREAKING NEWS` + 英文标题、底部红条字幕 | 只遮文字行，保留装饰边框 |
| 横屏填充片 | 上下模糊条 | 直接裁掉上下填充 |
| 平台水印 | 通常不存在 | 不用处理 |

所以 snaptik、开拍这类网页工具**不是必需的**，本地 ffmpeg 更快、更可复现。

## 一、下载

```bash
KIT="${KIT:-$HOME/tk-kit/kit}"   # 没设也能跑
cd "$KIT"
.venv/bin/python fetch.py out/links-2026-10-31.txt --out materials --frames 2
```

产物：

```
materials/
├── <id>.mp4           文件名用视频 id（跨平台安全、可反查）
├── meta/<id>.json     账号/标题/播放/时长/分辨率/有无音轨/链接
├── manifest.csv       汇总表
└── qc/<id>-N.png      质检帧（--frames 2 时生成）
```

幂等：已存在直接跳过；重下加 `--force`。

## 二、去水印（只遮文字行）

```bash
# 1) 先看它检测到哪些行（不渲染）
.venv/bin/python clean.py materials/<id>.mp4 --dry-run

# 2) 画一张带红框的预览图，确认位置对不对
.venv/bin/python clean.py materials/<id>.mp4 --preview

# 3) 渲染（默认把文字行填成深色 #101820）
.venv/bin/python clean.py materials/<id>.mp4

# 想要模糊而不是填色
.venv/bin/python clean.py materials/<id>.mp4 --mode blur

# 自动检测不准时，手工指定（y:height）
.venv/bin/python clean.py materials/<id>.mp4 --rows 88:280,1000:172
```

**检测原理**（脚本做的事）：抽 12 帧 → 每行算「时序标准差」把会动的画面区和不动的模板区分开 → 模板区里找白像素占比高 / 纯白底的行 → 合并成行段 → 按比例映射回原分辨率。

## 二b、遮蔽风格：三选一，按片子定

同一条片子三种遮法，观感差很远——**先选风格，再调区间**。

| 风格 | 命令 | 出来什么样 | 什么时候用 |
| --- | --- | --- | --- |
| **填色**（默认） | `clean.py in.mp4 --rows ...` | 文字区整块 `#101820` 深色，最干净 | 后面要盖自己的字幕，不在乎深色块 |
| **模糊** | `clean.py in.mp4 --rows ... --mode blur` | 保留底色纹理和装饰边框，只是糊 | 模板有花纹/渐变底（蓝电路板、光斑），填色突兀 |
| **保留装饰条**（两遍渲染） | ①`--rows 顶:高度,底:高度`（不含装饰条）②`--rows 文字行 --fill "<条色>"` | 红色装饰条留着、字没了，看着还是一条完整新闻模板 | 不想让画面「空一块」 |

### 实测量法（民生新闻模板 1080×1920）

```
BREAKING NEWS + 标题    y ≈ 118 – 542      ← 白色标题块
红色字幕条（整条）        y ≈ 1470 – 1600
其中白色文字             y ≈ 1496 – 1568
底部蓝色区说明字          y ≈ 1630 – 1780
```

- **全遮（默认观感）**：`--rows 118:424,1462:146,1630:150` → 吃掉 37.5% 画面高度
- **保留红条**：分两遍
  ```bash
  .venv/bin/python clean.py materials/<id>.mp4 --rows "118:424,1630:150" --out /tmp/passA.mp4
  .venv/bin/python clean.py /tmp/passA.mp4 --rows "1490:84" --fill "#8B1E1E"
  ```
  条色用吸色器从原帧取（这条是 `#8B1E1E`），不取色直接填深色会在红条上留一条黑带。

### 两个坑（都实测踩过）

- **只遮文字行 + 填深色** → 红条中间出现一条**黑色横带**，比不遮还难看
- **只遮文字行 + 模糊** → 半径 14 时**白字仍能读出来**（白粗体压红底，糊不掉）；要糊到不可读会把整条糊成色块，那就等于填色了。所以「保留红条」必须走上面的**换色填充**，不是模糊

**为什么必须 `--preview` 看一眼****为什么必须 `--preview` 看一眼**：字幕是渐变的、边缘有描边，自动检测通常会差 5–20 像素。看一眼红框位置，不对就用 `--rows` 手改，比盲信自动检测快得多。

## 三、判断标准（做完自己过一遍）

| 检查 | 合格线 |
| --- | --- |
| 文字 | 完全消失，没有半截字残留 |
| 边界 | 遮蔽紧贴文字，不多吃不必要画面 |
| 画面 | 中间主体没有被裁切 |
| 音轨 | 保留（配音阶段会替换，但原声要能听） |
| 尺寸 | 跟原片一致（不缩放，避免二次模糊） |

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 字幕还剩半截 | 检测边界偏内 | 用 `--rows` 手动扩 8–16px；模板红条常被 auto 只框住中间一段（实测 1470–1600 只框了 1504–1562） |
| `--mode blur` 报 `Cannot find a matching stream` | 旧版 filtergraph 的 crop 没接输入流、`[0:v]` 又被 overlay 消费掉 | 2026-11-01 已修（改成 `split=N+1`）；`cd ~/tk-kit && git pull && bash install.sh` 更新技能与脚本 |
| `--mode blur` 报 `Invalid chroma_param radius value 30` | 固定半径 30 超过窄带 21 的上限 | 已改为按带宽自适应 `radius=max(2,min(20,h//6))`，同样更新即可 |
| 跑完 `--preview` 多了个 `-clean.mp4` | `--preview` 不是 dry-run，它会顺带渲染 | 只想看框就先 `--dry-run`；已经渲染了想重来直接再跑一次覆盖 |
| 遮蔽区域吃到画面 | 文字紧贴画面边缘 | 缩小 `--rows` 范围，或改用 `--mode blur` |
| 整片都黑 | 画面本身是静态的（对话特写） | 时序分析误判，改 `--rows` |
| 视频是 1080×1920，坐标却对不上 | 用错分辨率算的 | 先 `tk.py probe` 确认真实尺寸 |
| 下载失败 | 代理没开 | `curl -x http://127.0.0.1:7890 ... https://www.tiktok.com/` 要 200 |

## 边界

- **不删**已下载素材；覆盖必须显式 `--force`。
- 不缩放、不转码画质（只做遮蔽 + 重编码）。
- 素材版权归原作者，仅用于分析/二创准备，**不要把 materials/ 提交进公开仓库**。
- 不自动发布；发布前的人工审核（血腥/水印/字体）永远是人的事。
