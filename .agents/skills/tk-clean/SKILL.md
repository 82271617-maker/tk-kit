# TK 素材准备：下载 + 去水印

一条命令把链接变成本地可剪素材；去水印**只遮文字所在的像素行**，不整块糊掉画面。

## 关键认知（先看这个，能省一半返工）

TikTok 的**平台水印在下载时就没了**（yt-dlp 拿的是源文件）。需要处理的其实是**原片自己烧录在画面上的文字**：

| 类型 | 长什么样 | 处理 |
| --- | --- | --- |
| 模板新闻片 | 顶部 `BREAKING NEWS` + 英文标题、底部红条字幕 | 只遮文字行，保留装饰边框 |
| 横屏填充片 | 上下模糊条 | 直接裁掉上下填充 |
| 平台水印 | 通常不存在 | 不用处理 |

所以 snaptik、开拍这类网页工具**不是必需的**，本地 ffmpeg 更快、更可复现。

## 一、下载

```bash
cd "$KIT"
.venv/bin/python fetch.py out/links-2026-10-31.txt --out materials --frames 2
```

产物：

```
materials/
├── <id>.mp4           文件名用视频 id（跨平台安全、可反查）
├── meta/<id>.json     账号/标题/播放/时长/分辨率/有无音轨/链接
├── manifest.csv       汇总表
└── qc/<id>-N.png      质检帧（--frames 2 时生成）
```

幂等：已存在直接跳过；重下加 `--force`。

## 二、去水印（只遮文字行）

```bash
# 1) 先看它检测到哪些行（不渲染）
.venv/bin/python clean.py materials/<id>.mp4 --dry-run

# 2) 画一张带红框的预览图，确认位置对不对
.venv/bin/python clean.py materials/<id>.mp4 --preview

# 3) 渲染（默认把文字行填成深色 #101820）
.venv/bin/python clean.py materials/<id>.mp4

# 想要模糊而不是填色
.venv/bin/python clean.py materials/<id>.mp4 --mode blur

# 自动检测不准时，手工指定（y:height）
.venv/bin/python clean.py materials/<id>.mp4 --rows 88:280,1000:172
```

**检测原理**（脚本做的事）：抽 12 帧 → 每行算「时序标准差」把会动的画面区和不动的模板区分开 → 模板区里找白像素占比高 / 纯白底的行 → 合并成行段 → 按比例映射回原分辨率。

**为什么必须 `--preview` 看一眼**：字幕是渐变的、边缘有描边，自动检测通常会差 5–20 像素。看一眼红框位置，不对就用 `--rows` 手改，比盲信自动检测快得多。

## 三、判断标准（做完自己过一遍）

| 检查 | 合格线 |
| --- | --- |
| 文字 | 完全消失，没有半截字残留 |
| 边界 | 遮蔽紧贴文字，不多吃不必要画面 |
| 画面 | 中间主体没有被裁切 |
| 音轨 | 保留（配音阶段会替换，但原声要能听） |
| 尺寸 | 跟原片一致（不缩放，避免二次模糊） |

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 字幕还剩半截 | 检测边界偏内 | 用 `--rows` 手动扩 8–16px |
| 遮蔽区域吃到画面 | 文字紧贴画面边缘 | 缩小 `--rows` 范围，或改用 `--mode blur` |
| 整片都黑 | 画面本身是静态的（对话特写） | 时序分析误判，改 `--rows` |
| 视频是 1080×1920，坐标却对不上 | 用错分辨率算的 | 先 `tk.py probe` 确认真实尺寸 |
| 下载失败 | 代理没开 | `curl -x http://127.0.0.1:7890 ... https://www.tiktok.com/` 要 200 |

## 边界

- **不删**已下载素材；覆盖必须显式 `--force`。
- 不缩放、不转码画质（只做遮蔽 + 重编码）。
- 素材版权归原作者，仅用于分析/二创准备，**不要把 materials/ 提交进公开仓库**。
- 不自动发布；发布前的人工审核（血腥/水印/字体）永远是人的事。
