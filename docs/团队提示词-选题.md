# 选题提示词（团队版）

> 用途：把「读账号表 → 抓取 → 筛选 → 出候选清单」固化成一条可复制的提示词。
> 配套：`kit/pick.py`（阈值）、`kit/pool.py`（抓取+判定）。改标准只改 `pick.py` 的 `THRESHOLDS`，不改提示词。

---

## 一、提示词正文（复制这一段给 AI）

```text
你是 TikTok 选题分析员。任务：从对标账号里选出「值得改写成日语版」的素材。

输入：飞书账号表 <链接>
输出：一张候选清单（Markdown 表格）+ 每个账号的基线 + 淘汰原因分布

【1】读表：解析所有账号（列：账号名称 / 链接）。链接只取 @handle，忽略 query 参数。

【2】取池子：每个账号取最近 20 条视频。
    抓不到主页时：用任意一条该号视频反查 channel_id，
    再用 tiktokuser:<channel_id> 拉列表。仍失败就写「未取到」，不要猜。

【3】算基线：每个账号分别算这 20 条的播放中位数。
    中位数 < 5 万的号标记为「小号」——小号只按绝对值判，不参与倍数。

【4】判定，顺序不能换：
  a. 一票否决（直接淘汰，不看数据）：
     血腥/政治/医疗绝对化；纯画面无叙事（换配音也没意义）；
     烧录字幕压在画面中部、裁不掉也盖不住。
  b. 硬门槛（全过才进候选）：
     播放 ≥ 100,000
     播放 ≥ 账号中位数 × 5（小号跳过这条）
     时长 45–90 秒
     点赞率 ≥ 1.0%
  c. 软分（不淘汰，只排序）：
     时效：≤14 天 5 分；15–30 天 3 分；>30 天 1 分
     评论率：≥0.05% 5 分；0.03–0.05% 3 分；<0.03% 1 分
     结构：能用「冲突→反转→结论」一句话说清的，5 分

【5】排序：按「软分 + 倍数」排，不单看播放。成本是 3 小时/条，
    选题要选「做得出来」的，不是「播放最高」的。

【6】输出格式：
    表格列：账号 | 播放 | 倍数 | 时效 | 点赞率 | 时长 | 标题 | 链接 | 结论 | 淘汰原因
    表下列出：各账号基线、淘汰原因分布（按条数）、已知限制。
    每条入选给一句「改写切入点」。

【7】交付（不能被省略）：入选的每一条都要交出「能直接用」的东西
    ① 纯链接清单：一行一条，去掉 query 参数，
       统一格式 https://www.tiktok.com/@账号/video/<id>，可直接复制发群
    ② 下载素材到 out/candidates/<id>.mp4，文件名用视频 id，别用标题
    ③ 清单末尾给出：条数、素材目录、生成日期
    只给标题不给链接 = 没交付。

禁止：
- 不要跨账号比倍数，每个号各算各的
- 不要因为播放低就淘汰结构好的片子（软分排序，不是淘汰）
- 不要输出没有原始链接的条目
- 不要编造播放/点赞数据
```

## 二、流程长什么样

```text
读表 ─► 取池子(20条/号) ─► 算基线(中位数) ─► 判定 ─► 排序 ─► 交付
                                           │                  │
                              ① 一票否决 安全/叙事/字幕位置      ① 纯链接清单
                              ② 硬门槛  10万·×5·45–90秒·点赞1%   ② 素材下载到 candidates/
                              ③ 软分    时效·评论率·结构         ③ 条数+目录+日期
```

**顺序不能换**：先否决，再门槛，最后软分。反过来做会让“安全不过关但数据漂亮”的片子混进候选。

## 三、参数表（改这里 = 改标准）

| 参数 | 当前值 | 位置 | 依据 |
| --- | --- | --- | --- |
| 绝对播放底线 | 100,000 | `pick.py: abs_views_floor` | 10 万 ≈ 被推荐池验证过一轮 |
| 相对倍数 | ×5 | `pick.py: rel_multiple` | 13–20 条样本里，跑赢 5 倍基本能排除“账号带量” |
| 小号阈值 | 中位数 < 50,000 | `pick.py` 判定逻辑 | 小号倍数噪声大（实测 3,145 中位的号出现 56 倍） |
| 时长区间 | 45–90 秒 | `pick.py: dur_min/dur_max` | 短了没改写空间，长了配音/留存都掉 |
| 点赞率 | 1.0% | `pick.py: like_rate_min` | 三个号点赞率中位数在 1.3–2.6% 之间 |
| 时效 | 软分（原为硬门槛 ≤30 天） | 提示词第 4c 步 | 日语受众不会比对原片时间，硬门槛误杀 3 条 60–95 万 |
| 评论率 | 软分（原为硬门槛 0.03%） | 提示词第 4c 步 | 对“可做性”几乎没解释力，曾误杀 120 万 / 4.08% 的片子 |

### 各账号基线

| 账号 | 中位数 | 类型 |
| --- | --- | --- |
| @fmghpfiq6aqplco | 3,145 | 小号（只按绝对值判） |
| @majftjbdgan | 133,350 | 大号 |
| @johnstonmose | 49,100 | 中号 |

### 淘汰原因分布（60 条实测）

| 原因 | 条数 |
| --- | --- |
| 绝对播放 / 相对倍数不足 | 约 40 |
| 时效超 30 天（改软分后可回升） | 3 |
| 评论率不足（改软分后可回升） | 1 |

### 已知限制

- 主页抓取偶发失败：脚本已内置 channel_id 兜底 + 3 次重试；仍失败写「未取到」。
- 播放数含推荐位波动，同一条隔天看可能差 10–20%，只看量级。
- 英语区基线不能直接套日语区，日语市场要单独建基线。

## 五、团队怎么用

1. 每个人装一次 `kit`（`.venv` + 脚本），或者由一个人跑、把结果贴群里。
2. 每个阶段只用一条提示词，输出格式固定，方便横比和汇总。
3. 想调标准：只改 `pick.py` 的 `THRESHOLDS`，**不要各自改提示词**，否则同一个片子两个人判出两个结论。
